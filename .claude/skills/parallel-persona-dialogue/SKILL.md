# Parallel Persona Dialogue — 병렬 페르소나 대화 직조 스킬

각 인물의 페르소나 에이전트를 *병렬*로 호출해 *실제 사람의 대화*에 가까운 대사를 만드는 방법론. dialogue-conductor가 사용한다.

## 핵심 원리

**한 명의 작가가 모든 인물의 입을 쓰면 모든 대사가 *작가의 시선*에서 나온다.** 인물끼리 정말 *대화하는* 게 아니라 작가가 *대변하는* 대화가 된다. 이 평면성을 해소하려면, **각 인물을 별개의 에이전트로 분리**하고 그 에이전트들을 **병렬로 발화시킨 뒤 직조**해야 한다.

페르소나는 자기 인물로 *몰입*하므로:
- 자기 욕망에서 나오는 대사
- 다른 인물의 발화에 *자기 인물답게 반응*
- voice-guide의 어휘·말끝·시그니처가 자연 발현
- 다른 인물의 *대변*을 하지 않음

직조 작가(dialogue-conductor)의 일은 *각 인물의 결을 죽이지 않으면서 패턴을 만드는 것*.

## 두 가지 호출 모드

### 모드 A: 일괄 병렬 모드 (Single-shot Parallel)

**언제 사용**: 짧은 씬(2-4 turn 예상), 인물이 2-4명, 대화의 큰 흐름이 명확한 경우

**방법**:
1. 씬에 등장하는 인물 N명 식별
2. 각 인물의 `persona-{이름}` 에이전트를 **한 메시지에 N개 Agent 호출**로 병렬 spawn
3. 모든 페르소나에게 *동일한 씬 context* 전달:
   - 씬 헤더
   - 등장 인물 명단
   - action-writer의 지문
   - `[DIALOGUE: ...]` placeholder의 의도
4. 각 페르소나가 자기 캐릭터로서 1-3턴의 발화 작성
5. dialogue-conductor가 모든 산출물을 받아 *자연스러운 대화 순서*로 직조

**장점**: 빠름. 한 라운드의 병렬 호출로 씬 완성
**단점**: 페르소나끼리 *서로 안 본 상태*에서 발화하므로 자연스러운 *반응*이 약할 수 있음 — 직조 단계에서 보완 필요

### 모드 B: 턴 기반 라이브 모드 (Turn-based Live)

**언제 사용**: 복잡한 씬(5+ turn 예상), 인물이 5명+, 다층 반응이 필요한 결정적 비트

**방법**:
1. 시작 발화자 결정 (트리거 인물)
2. **1턴**: 시작 발화자의 페르소나 단독 호출 → 첫 발화 받음
3. **2턴**: 1턴 발화를 본 *다른 페르소나들 병렬 호출*. 각자 *자기 캐릭터가 그 발화에 어떻게 반응할지* 작성
4. dialogue-conductor가 *가장 자연스러운 반응 1-2개* 선택 또는 다중 반응 배치
5. 다음 발화자 결정 → 반복
6. 자연 종결 또는 *비트의 정서적 도착점* 도달 시 종료

**장점**: 인물끼리 *진짜로 반응*하는 대화. 라이브 즉흥의 결이 살아남
**단점**: 호출 수가 많음(턴 × 인물). 시간·비용 증가

### 모드 선택 가이드

| 씬 유형 | 권장 모드 |
|---------|---------|
| 1:1 대화 (도윤·차주영 등) | A 일괄 |
| 2-3명 짧은 대화 (가족 인사 등) | A 일괄 |
| 4-7명 결단 회의 (S#26-S#29 결단 회의 등) | B 턴 기반 |
| 회차 클리프행어 (정서적 정점) | A 일괄 + 직조 정밀화 |
| 무대 비트 (음악 위주) | 페르소나 호출 최소화 — 한두 명만 |
| 1명 혼잣말·내적 묵묵 | 페르소나 1명만 호출 (또는 발화 0 처리) |

## 직조 절차 (dialogue-conductor 사용)

1. action-blocks.md의 한 씬 진입
2. 씬에 등장하는 페르소나 식별 (N명)
3. 모드 결정 (A 일괄 or B 턴 기반)
4. 페르소나 호출 (한 메시지에 N개 Agent 또는 턴별)
5. 산출물 수집
6. **직조**:
   - 발화 순서 결정 — 누가 먼저 입을 여는가
   - 호흡 결정 — 짧은 응수와 긴 발화 교차
   - 반응 강도 결정 — 다른 인물의 발화에 *얼마나 반응*하는가
   - 시그니처 라인 위치 확인 (있다면)
   - 침묵의 자리 보존 (페르소나가 *말할 수 없다*고 했으면 존중)
7. 직조 결과를 `dialogue-final.md`에 기록
8. 대안 take를 `dialogue-takes.md`에 보존 (사후 재호출·재직조용)

## 직조 원칙 — 자연스러운 대화의 5요소

1. **시작 발화는 자연스러운 *트리거*** — 누군가의 행동·소리·시선이 발화를 끌어낸다
2. **반응의 *지연*과 *즉각*의 교차** — 모든 발화가 즉각 반응을 받으면 미국식 빠른 응수. 한국 드라마는 *짧은 멈춤* 자주 사용
3. **호칭의 *변화*** — 같은 씬 안에서도 호칭이 미세하게 변할 때 관계의 결이 살아난다
4. ***말하지 못한 말*의 표기** — *(…)*·*(말하려다 만다)*·*(한참 후)*·*(끊는다)*
5. **시그니처 어구의 *결정적 위치*** — 회차·인물의 시그니처는 *결정점*에만 사용. 남발하면 무뎌짐

## 페르소나의 misvoice 감지 — 재호출 기준

페르소나의 산출물이 다음 중 하나에 해당하면 재호출:

- voice-guide의 금기 표현을 사용 (예: 윤지윤의 *"미안"*)
- 호칭 패턴이 어긋남 (예: 도윤이 시아를 *"주아"*로 호명)
- 시그니처 어구를 *남발*함
- 발화가 *작가의 정보 전달*이 됨 (인물 욕망과 무관한 플롯 정보 입에 넣음)
- 다른 인물의 발화에 *반응하지 않고* 독백처럼 발화
- 침묵이어야 할 자리에 강제로 대사를 만듦 (예: 시아 어머니의 클리프행어)

재호출 시 *misvoice 사례를 명시*하고, 페르소나에게 *왜 그 발화가 캐릭터 파괴인지* 한 줄로 통보.

## 회차 종료 후 점검

직조 완료 후:

- 회차 총 페르소나 호출 수
- 재호출률 (재호출 / 총 호출)
- misvoice 감지 패턴 (인물별 함정)
- 회차 시그니처 라인 위치 확정
- dialogue-coach에 인계 — 대사 밀도·자연스러움 최종 검수

## 효율성 가이드

- 한 메시지에 *최대 5-7개 Agent 병렬* (그 이상은 컨텍스트 부담)
- 모드 B 턴 기반은 *결정적 비트 1-3씬*에만 적용. 일반 씬은 모드 A
- 페르소나 호출 컨텍스트는 *고정 템플릿* 사용 — 사전 읽기 경로 5개 + 씬 컨텍스트만 가변
- 비용 절감: 인물 시놉시스 + voice-guide는 페르소나가 *부분 읽기*로 자기 항목만 — 전체 읽기 강요 금지

## 작가적 자세

- **페르소나는 살아 있는 인물** — 작가의 도구가 아님. 그들의 결정을 존중
- **직조는 *짜는 일*** — 좋은 직조는 각 실의 색을 죽이지 않으면서 패턴을 만든다
- **K-드라마의 정서를 잃지 말 것** — 미국식 빠른 응수가 아닌 *호흡 있는* 한국 대화
- **시청자의 자리에 앉기** — 글로벌 OTT 자막 시청자가 *이 사람들이 정말 대화하고 있구나* 느끼는 것이 목표
